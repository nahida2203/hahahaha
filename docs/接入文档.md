# 福农AI创 · Grok 多模态模型接入文档

> 版本：v1.0 ｜ 适用范围：funong-user-mvp-quick-create 前端项目

本文档说明如何将 **grok-imagine-image**（图像生成）与 **grok-imagine-video**（视频生成）
两个 AI 模型接入本项目，以及本次"硬编码配置数据源化 + AES-256 敏感信息加密"改造的全貌。

---

## 1. 架构总览

```
┌────────────────────────────────────────────────────────────┐
│                         浏览器（Vue 3 应用）                │
│                                                            │
│  config.yaml (public/) ──→ configLoader ──→ grokClient      │
│     ├─ ai_models.*        (AES-256 解密)   └── axios-retry  │
│     └─ settings.*                                          │
│  appData.yaml (public/data/) ──→ appDataLoader              │
│     ├─ channels / templates / assets ...                    │
│     └─ demo_accounts（密码密文，加载时解密）                  │
│                                                            │
│  contentGenerator ──→ generateGrokImage（图像模型，同步）     │
│                  └── generateGrokVideo（视频模型，异步轮询）  │
│                                                            │
│  CreateResultView ──→ 展示生成结果 / 降级警告 / 额度扣减      │
└────────────────────────────────────────────────────────────┘
         │  HTTPS（Authorization: Bearer <key>）
         ▼
  xAI API (api.x.ai)
```

- **图像生成**：`POST /v1/images/generations`，同步返回图片 URL / Base64。
- **视频生成**：`POST /v1/videos/generations` 提交任务 → 返回 `request_id` →
  轮询 `GET /v1/videos/{request_id}` 至 `done`，返回视频地址。

> 本项目当前通过中转站 `https://sub2api.tegical.com` 调用上述接口（端点见 `config.yaml`，
> 可随时切换为官方 `https://api.x.ai` 或其他 OpenAI 兼容网关，模型名保持不变）。

## 2. 接入流程

### 2.1 安装依赖

```bash
npm install js-yaml crypto-js axios axios-retry
npm install -D vitest jsdom @vue/test-utils @types/js-yaml @types/crypto-js
```

### 2.2 配置加密密钥（首次必做）

1. 复制 `.env.example` 为 `.env`：

   ```bash
   copy .env.example .env
   ```

2. 设置强随机密钥 `VITE_CRYPTO_KEY`（建议 ≥ 32 位随机字符）。**该文件已被 `.gitignore` 忽略，严禁提交仓库。**

### 2.3 写入真实 API Key（加密后）

1. 使用仓库内工具加密你的 xAI API Key：

   ```bash
   node scripts/encrypt-key.mjs "xai-<你的真实Key>" --key "你的VITE_CRYPTO_KEY"
   ```

2. 将输出的密文填入 `public/config.yaml` 的 `ai_models.grok_image.api_key_encrypted`
   与 `ai_models.grok_video.api_key_encrypted`（两个模型可共用同一把 Key，也可分开）。

### 2.4 校验配置

```bash
npm run dev
```

打开应用后检查控制台：

- `GET /funong-ai-create/config.yaml` 与 `GET /funong-ai-create/data/appData.yaml` 均返回 **200**；
- 无 `系统配置加载失败 / 应用数据加载失败` 报错。

### 2.5 触发真实模型调用

- **图片生成**：首页 → 图片生成 → 填写描述 → 制作 → 开始生成。成功时结果区展示 AI 海报（来源标记"AI 海报"）。
- **视频生成**：首页 → 视频生成 → 填写描述 → 制作 → 开始生成。成功时结果区展示视频播放器（来源标记"AI 视频"）。

> 未配置有效 Key 或网络不可达时，调用将按重试策略重试，重试耗尽后按 `fallback_to_local`
> 配置降级为本地示例素材并弹出警告（详见 §4.3），保证演示流程不中断。

## 4. 关键机制

### 4.1 重试与稳定性（99.9% 目标）

- **重试条件**：网络错误、HTTP 429（限流）、5xx（服务端错误）。
- **退避策略**：`retryDelay * 2^(n-1)` + 随机抖动（≤200ms），避免重试风暴。
- **超时控制**：请求超时、视频任务轮询超时均由配置驱动，杜绝无限等待。
- **轮询容错**：视频轮询单次请求失败不中断任务，下一轮继续。

### 4.2 安全合规

- 敏感字段（API Key、演示密码）以 AES-256 密文存于 YAML，运行时解密仅驻留内存，不落盘、不打日志。
- `.env` 存放解密密钥，已加入 `.gitignore`，提交仓库只含 `.env.example` 占位。
- 建议生产环境：将 `VITE_CRYPTO_KEY` 注入构建/运行时环境变量，并在网关层代理 xAI 请求，避免浏览器直连。

### 4.3 降级策略

每个模型可在 `config.yaml` 中独立配置：

| 配置项 | 说明 |
| --- | --- |
| `enabled: true` | 启用真实模型调用 |
| `fallback_to_local: true` | 调用失败（重试耗尽）后降级本地示例素材，并在结果页展示警告条 |
| `fallback_to_local: false` | 调用失败直接进入错误态，引导用户重试 |
